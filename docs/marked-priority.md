# 0.7.14 可选标记主动转火

0.7.13中标记只影响到达普通轮换时间后的排序；旧目标未进入攻击状态时还会等待超时，随后选最近敌人。0.7.14让实时有效的其他标记目标成为独立重选触发条件。

## 触发与边界

控制器约20Hz轮询。没有未结束事务、无人机处于已核对的节点6/7且已有非零目标时，策略找到与本地标记完整身份一致的可选候选，就可以立即提出`reason=marked_priority`、`selection_basis=player_mark`请求。无需积累普通0.4秒攻击窗口，也不用等待旧目标1.5秒未攻击超时。旧目标超时同帧仍可优先转向这个新的可选标记。

请求仍临时限制其他候选并推进原生重选期限，不直接写目标ID；提交前重新校验标记、身份、快照和事务地址，实际目标切换及开火由游戏执行。轮询频率不意味着保证50毫秒切换或命中。

- 标记必须实时可选。只有原始标记观察、非正评分、候选缺失、身份不匹配均不能触发主动标记请求；1.5秒宽限只保护已有的标记锁定。
- 标记目标等于当前目标时不反复请求自己，沿用4秒攻击、3秒连续未攻击、5秒最长锁定和1.5秒评分宽限。
- 保留Recent一条/一秒规则：近期处理目标不获得主动标记优先。普通候选全都在Recent时原有回退策略仍保留，因此这不是额外的硬禁止攻击期。
- 主动标记请求提交后最短间隔0.5秒。换标或原生暂时选到其他目标不会清除此冷却；新玩家/背包上下文会清理状态。未提交事务不记为已发出的请求。
- 普通请求仍有0.15秒重试间隔；正在执行的事务先恢复并重新采样，不被新标记直接覆盖。实际写入租约上限仍0.25秒。
- 从打不到的当前标记目标触发3/5秒兜底时，仍选择其他敌人；当前目标排除及Recent避免立即以标记优先抢回它。
- 节点3、无当前目标或无法核对必要身份时，等待原生进入可重选状态。此次没有扩大可写状态范围。

## HUD 与日志

实际请求显示绿色`MOD: MARKED`，Next为请求目标；日志`active_reason`或`last_request_reason`为`marked_priority`。绿色标记还在等待时，`mark_wait_reason`解释条件：

| 值 | HUD |
| --- | --- |
| recent | recent target; waiting |
| retry | request cooldown |
| native_state | waiting for native targeting |
| identity | waiting for target identity |
| ready | requesting marked target |

黄色`MARKED: WAITING`与其score/missing等原因保持0.7.13行为。本次没有实现限频原生重新评分，也没有重建感知候选列表；不能将此版本视作这两类问题的修复。

测试见`tests/test_core.lua`、`tests/test_hud.lua`及[验证记录](validation.md)。v14/v15各生成HUD与No HUD，共四包；游戏中验证需部署并重启加载新版本。本机安装版本以`build/deployment.json`和新进程日志为准。
