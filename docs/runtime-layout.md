# 运行时布局与研究依据

本页是 **Steam build 24826606 / EXE 1.8.45317.0** 的研究记录，不是跨版本 API。字段名是根据用途赋予的名称，不是恢复出的完整官方类型声明。

## 版本与地址约定

| 输入 | 已校验 SHA-256 |
| --- | --- |
| `bin/helldivers2.exe` | `A09FF52663E73B94FB0CAC0DCB5BA84FFD10ECF44F74A8921AC66AF923988CC3` |
| `data/game/game.dll` | `CC75948D90FDFDE259DCB519E9933DB7FFA3CCB281CE4FB89E6B1B011557470C` |

启动签名：`game.dll + 0x6b7f20` 的前 24 字节为 `405741574883ec283b1532ed0c02450fb6f94c8b15074b0b`。该处仅用于版本/布局校验；本项目不调用这个函数。

下表中的 RVA 均相对**运行中加载的 game.dll 基址**。不能当成磁盘文件偏移，也不能跨进程复用绝对地址。原开发时磁盘模块的代码与加载后展开的代码不同，直接按 RVA 读磁盘不能取得对应指令。

版本校验分别存在于 `scripts/build.py` 生成的入口配置、`scripts/deploy.py`、外部观察器及其 `research/observe_rover.py` 依赖。升级时必须一起核对；仅改哈希让旧偏移通过不是适配。

## 管理器与归属链

所有“根 RVA”处存的是管理器指针。偏移列中的十进制不带 `0x`，十六进制带 `0x`；以下沿用源码写法。

| 管理器 | 根 RVA | 本项目使用的字段 |
| --- | --- | --- |
| 模式 | `0x276c3d0` | `+8` 非零且 `+0x40 == 1` 才继续任务处理 |
| 玩家 | `0x276c190` | 人数 `+0x84/+0x88`；本地 unit `+0x3a8` |
| 实体归属 | `0x276f0c0` | unit map `+0xf21a88`；内联实体数组 `+0xf31ad8`，stride 24 |
| 装备 | `0x276c468` | map `+40`；实体指针数组 `+64`；runtime 指针 `+80`，stride 48，背包 ID 在记录 `+12` |
| 背包 | `0x276c318` | active count `+0x10`；实体指针数组 `+0x38`；link 数组 `+0x50`，stride 8，link `+4` 对应无人机实体 `+16` |
| 附件 | `0x276cad0` | map `+32`；runtime `+64`，stride 48，holder ID `+4` |
| Targeting | `0x276ca40` | 容量/总数/活动数 `+308/+320/+324`；map `+336`；实体指针数组 `+360`；runtime `+376`，stride 208，目标 ID `+0` |
| Behavior | `0x276c470` | 容量 `+32`；map `+64`；实体指针数组 `+88`；runtime `+96`，stride 496 |
| 感知 | `0x276c270` | map `+48`；实体指针数组 `+72`；runtime `+80`，stride `0x13f8` |
| 阵营实体 registry | `0x276c9c8` | map `+73808`；实体指针数组 `+73832`，用于重新确认候选敌人身份 |
| 原生时钟 | `0x276c068` | `+24`，uint64 微秒时间 |

运行路径为本地 unit → avatar → 装备中的背包 → 背包 link 的无人机 reference → Targeting 中同 reference 的激光狗，再用 Behavior/Perception 的实体指针进行交叉验证。背包还必须附着在该 avatar 上。不是发现任意 Behavior 189 就修改它。

哈希 map 头部是 20 字节：数据指针 `+0`、容量 `+8`、空 key `+12`、乘数 `+16`；每个槽 8 字节，key/value 各 uint32。容量必须是 2 的幂，索引按 uint32 乘积和线性探测求出；最多探测 128 次，具体容量上限由调用处限定。

## Behavior 与候选记录

| Behavior runtime 偏移 | 当前解释 |
| --- | --- |
| `+0` | Behavior ID，激光狗要求 189 |
| `+8` | 当前节点，策略仅在 7 工作 |
| `+24` | 选中目标 ID |
| `+96` | 目标来源标志，检查 bit 0 |
| `+104` | 感知观察者 ID，必须等于无人机 ID，拒绝共享感知 |
| `+112` | 前一目标相关字段，原生分析线索，当前不写 |
| `+120` | 目标有效字节 |
| `+152` | 下次选敌期限，uint64 微秒，当前会临时写入 |
| `+360` | 节点进入计时相关线索，当前不使用 |

原生节点函数的 context 中：`[context+0]` 是实体，`[context+8]` 指向 Behavior runtime `+8`。所以原生源码中基于该第二指针的 `+0x90` 对应完整 Behavior runtime 的 `+152`。不要混淆两套基准。

感知 runtime 中阵营筛选项数在 `+0`；条目从 `+8` 开始，每项 8 字节，首个 uint32 为阵营 bit 编号。当前实现将它们合成 allowed mask，检查数量不超过 32、bit 编号小于 32。

| 候选区域 | 数量偏移 | 记录起点 | 每组上限 |
| --- | --- | --- | --- |
| 组 1 | `0x310` | `0x318` | 16 |
| 组 2 | `0x818` | `0x820` | 16 |
| 组 3 | `0xd20` | `0xd28` | 16 |
| 特殊项 | 单项 `+0x48` 非零表示参与 | `0x1228` / `0x1278` / `0x12c8` | 各 1 |

每条候选 stride 80 字节：

| 记录偏移 | 类型 | 用途 |
| --- | --- | --- |
| `+0` | uint32 | 目标 ID |
| `+68` | float | 缓存的原生评分；要求有限、绝对值小于 100000，可用候选要求 >0 |
| `+72` | uint32 | 来源标志；检查 bit 0，也对应特殊项存在标记的位置 |
| `+76` | uint32 | 阵营资格掩码；当前唯一被临时改写的候选字段 |

上限是代码和原生布局的约束，不是已完成的压力测试规模。实机较密集场景最多观察到 14 条候选、13 条可用候选，还没有验证全部分组和特殊项组合的极限。

## 为什么这个修改会影响原生选敌

以下来自本机加载后代码的离线反汇编，以及激光/毒气两组运行时观察。没有直接调用下列游戏函数。

| 线索 | RVA | 意义 |
| --- | --- | --- |
| Behavior 分派 | `0x46b630`，表 `0x471808` | 按 Behavior ID - 1 分派；用已有哨戒炮入口交叉核对 |
| 激光节点 3 / 6 / 7 | `0x25f680` / `0x2609d0` / `0x261b50` | 激光狗状态处理路径 |
| 激光转换辅助 | `0x262e20` | 状态转换分析线索 |
| 毒气节点 3 / 6 / 7 | `0x25b9d0` / `0x25c9f0` / `0x25db00` | 对照路径，不能直接替换给激光狗 |
| 毒气转换辅助 | `0x25ed00` | 对照线索 |
| 感知索引解析 | `0x87f890` | 由观察者解析感知索引 |
| 候选提取 | `0x87f9a0` | 分组及特殊候选读取 |
| 阵营资格检查 | `0x87ba20` | 检查候选 `+76` 与观察者阵营条件 |
| 原生设置目标 | `0x4aa790` | 拷贝 80 字节目标记录并维护关联状态 |
| 背包关联路径 | `0x4da5ed`–`0x4da647` | 支持背包 link → 无人机 reference 的解释 |

激光评分路径在 `0x2620f2` 调用阵营检查；布尔结果转换后的浮点因子在 `0x262285` 存到 `[rsp+0x74]`，在 `0x262882` 乘入候选评分。掩码置零会使该因子为零，原生选择路径只考虑正分候选。Mod 随后把期限推进到当前原生时间，使原生逻辑尽快重新选择。

从反汇编能解释字段作用，实机记录又支持目标轮换发生；这仍不能推导出每次光束命中或点燃。直接只写目标 ID 会遗漏原生维护的记录与关联状态，因此当前没有采用。

## 游戏升级时的复核顺序

先保留旧版本证据，核对新 EXE/DLL 哈希；在不安装写入补丁的情况下定位加载后的签名和分派路径。依次重新证明玩家归属、背包 link、无人机资源与行为、候选布局、评分因子和时钟单位，再更新快照 fixture 和编译入口。

先跑只读采样验证船上/任务切换和不同敌人，再启用最小范围的实验写入并验证恢复。旧版本 `MEM_PRIVATE/PAGE_READWRITE` 检查只说明页面属性合适，不证明新版本偏移语义正确。
