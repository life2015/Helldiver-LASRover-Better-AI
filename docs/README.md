# 维护文档索引

文档基线：实验版 **0.3**，整理于 **2026-09-18**。读者无需了解最初的开发对话。

项目让激光护卫犬漫游车在短暂攻击后更频繁地更换目标。目标是帮助铺开点燃，但实现**没有读取燃烧状态**，计时也不等于实际激光命中时长。已有两组实机战斗记录支持“更频繁转火”，不代表全部敌人兼容。

## 从哪里开始

| 想做的事 | 文档 |
| --- | --- |
| 了解代码分工、轮换策略和临时修改如何恢复 | [实现架构](architecture.md) |
| 查版本、哈希、资源身份、内存布局和原生函数线索 | [运行时布局与研究依据](runtime-layout.md) |

首次接手建议按“架构 → 开发 → 部署 → 调试 → 验证”阅读；适配游戏更新时再详细核对布局文档。

## 文档与源码的关系

`src/` 是执行逻辑，`scripts/` 是构建、部署和外部观察工具，`tests/` 是隔离测试。这组文档记录当前实现及证据；发生分歧时，先核对实际安装包、构建报告及源码，不能只按文档里的地址写内存。

历史流水记录仍在同级工作区的 `research/rover-investigation.md`。其中“下一步”“尚未完成”等措辞描述的是当时状态；本目录已按当前状态重新整理。`research/artifacts/` 中的原始采样、模块快照和反汇编仅在原开发工作区保存，不要求公开读者拥有这些文件。

当前项目仍有同级目录依赖，尚未完成独立仓库整理；详见[开发与构建](development.md)和[维护与公开发布准备](maintenance.md)。文档已便于移交，不等于已选定开源许可证或完成公开发布。

## 维护这组文档

行为变化更新 `architecture.md`；偏移或支持版本变化更新 `runtime-layout.md`；构建、启动入口变化更新 `development.md` / `deployment.md`；新问题和新测试分别追加到 `debugging.md` / `validation.md`。每次实机结论应带上包版本、游戏版本、采样条件和已知限制，避免把“测试通过”扩大成未经验证的兼容声明。
