# 激光狗索敌优化：玩家安装说明

适用版本：0.7.4；更新于2026-09-19。安装成品ZIP不需要Python、源码或单独的注入器。
0.7.4新增同目标1.5秒兜底：短暂切换攻击/瞄准状态不会无限重置进度；有其他有效候选时尝试重选。成功提交请求、换目标或观察失效后重新计时。正常0.4秒攻击转火优先，仍不读取伤害或点燃。

## 选择安装包

每个渠道都有HUD测试版和No HUD无界面版，六包只能选一个。包名里的v12/v14/v15是加载器渠道，0.7.2才是本Mod版本。

| 渠道 | HUD版ZIP | 依赖 |
| --- | --- | --- |
| v12 | `激光狗索敌优化-0.7.4-v12-内置加载器.zip` | 内置固定v12 |
| v14 | `激光狗索敌优化-0.7.4-v14-内置加载器.zip` | 内置完整官方v14 |
| v15 | `激光狗索敌优化-0.7.4-v15-需要额外安装加载器.zip` | 另装[官方Bingus Shared Loader v15](https://github.com/CowboyBingus/BingusSharedLoader/releases/tag/v15) |

无界面版在对应名称末尾增加`-No-HUD.zip`，保留相同索敌与文本日志，不包含HUD绘制模块。用于观察时选HUD，确认效果后可换No HUD；它不是已确认的崩溃修复。完整六包名称见[多渠道说明](packaging-channels.md)。

已有官方v15环境可选v15包；保留v14环境可选内置v14包。其他Mod只是依赖v14时通常可以由v15加载，但内置旧加载器、自定义启动脚本或也修改激光狗的Mod仍需检查，不能保证任意组合兼容。

## 功能

激光漫游车在约0.4秒同步攻击状态后尝试换目标。通常先避开近期记录，再选靠近当前目标的其他有效敌人；当前目标距漫游车超过15米且圈内有替代目标时，先转回15米内。当前目标已在15米内时不强制下个目标也留在圈内。

近期记录最多1个、1秒过期。同一目标约1.5秒未进入同步攻击状态时，尝试改锁离漫游车最近的其他目标；没有替代目标就继续原生行为。原生游戏负责瞄准和攻击，Mod不读取燃烧状态，不保证实际命中、点燃或严格照射时间。

## 使用Mod管理器安装

1. 正常退出游戏，保留旧ZIP及管理器配置。禁用旧Rover包并部署移除；包括旧英文名版本和其他加载器渠道、HUD变体。
2. 导入所选安装ZIP，启用。若收到外层分享包，先解压，再导入其中的安装ZIP；不要把回退包一起启用。
3. 按所选渠道配置加载器和启动资源优先级：v12/v14让Rover启动桥生效；v15单独启用官方v15，让官方加载器生效。Arsenal默认优先级的获胜包放最后，首项优先模式则放最前；以实际资源覆盖结果为准。
4. 部署后从Steam正常启动，无需更改启动参数。

v12/v14包已经内置加载器，不必再额外装同版独立加载器。保留独立条目用于停用Rover后的其他Mod时，需要核对覆盖关系。v15包本身没有Wwise/boot资源；若显示此类覆盖，检查旧Rover包是否残留。详细规则见[v14](shared-loader-v14.md)和[v15](shared-loader-v15.md)说明。

## 手动安装

已有管理器的玩家继续使用管理器，避免混用编号和卸载记录。

1. 正常退出游戏，按自己的记录移除旧Rover三个文件。解压所选ZIP到临时目录。
2. v12/v14使用ZIP中`data`内的三个文件；v15使用`Addon`内的三个文件，并按官方说明单独安装加载器。两者最终都放入游戏的`data`，不要创建`data/data`或`data/Addon`。
3. 在游戏`data`中查找`9ba626afa44a3aa3.patch_`前缀，使用最大现有编号加一，没有则从0开始。三个文件统一改成相同编号，示例如下；不要覆盖已有文件。

   ```text
   9ba626afa44a3aa3.patch_3
   9ba626afa44a3aa3.patch_3.stream
   9ba626afa44a3aa3.patch_3.gpu_resources
   ```

4. 复制后记下确切文件名、包名和游戏目录，留作卸载依据。两个附属文件为0字节正常。出现替换提示就取消并核对编号。
5. 从Steam启动。多个启动包之间仍需符合对应渠道的覆盖关系；空编号本身不保证兼容。

默认游戏目录是`C:\Program Files (x86)\Steam\steamapps\common\Helldivers 2`，以Steam显示的实际位置为准。示例patch_3不代表每个人都应该使用3。

## 确认加载和观察转火

所有渠道的运行日志为`%LOCALAPPDATA%/RoverFireSpread.log`，检查本次修改时间、进程ID、`build_id=experimental-0.7.4`和持续增长的`samples`。飞船内等待任务正常。

HUD版在顶部居中显示面板：

| 显示 | 含义 |
| --- | --- |
| `WAITING` | 等待任务、本地激光狗或数据 |
| 绿色`MOD: NEAREST` | Mod正在按距离策略提交临时选敌请求 |
| 黄色`MOD: NATIVE PICK` | Mod筛选候选，由原生评分挑选具体目标 |
| 绿/黄标题带`(last)` | 请求已结束，颜色额外保留0.5秒便于观察 |
| `NATIVE` | 当前没有活动请求，不代表Mod停用 |
| `STOPPED` | 控制器出现错误，检查日志及清理状态 |
| `Locked` / `Next` | 已同步当前目标 / 请求目标；Next保留到提交后2秒并标注(last)，不保证已锁定 |

`adjacent target`表示按目标间距离，`near Rover (15m)`表示从远处优先转回近处。目标ID是可能复用的运行时编号，不是敌人类型。更多细节见[HUD说明](hud.md)。

No HUD版没有界面，成功运行后日志显示`hud_enabled=false`、`hud_status=disabled`。HUD版也可能因字体布局不匹配而只关闭界面，不能仅凭无面板判断Mod是否加载。

启动诊断按渠道区分：v12/v14看`%LOCALAPPDATA%/RoverFireSpread-startup.log`；v15看`%LOCALAPPDATA%/CowboyBingus/Helldivers2/Logs/BingusSharedLoader.log`的发现/加载记录，旧Rover启动日志不会更新。加载器的loaded还需结合Rover主日志确认。

## 更新、切换、回退和卸载

正常退出游戏，先移除当前Rover，再安装目标版本或HUD变体。管理器安装通过同一管理器禁用并重新部署；手动安装只删除自己记录的三个文件，再记录新包实际文件。不能在游戏运行中替换，也不能叠加两个Rover版本。

迁移到v15时，移除旧Rover启动包，用官方v15替换独立旧加载器，再启用v15 Addon。回退内置渠道时重新核对启动覆盖关系。仅停用Rover无需降级官方v15；保留其他Mod所需的加载器。

卸载不需要修改存档；残留日志不会加载Mod。不要删除整个data，也不要按归档前缀批量删除其他Mod。

## 已知限制和反馈

布局基线为Steam build 24826606 / EXE 1.8.45317.0。整文件哈希不同可尝试运行，但关键签名、身份及结构检查仍必须通过。当前实验版尚未全面验证不同敌人、联机与所有Mod组合。近期整机卡死/黑屏的根因未确认，调查见[故障记录](crash-investigation-2026-09-19.md)。

反馈时提供：完整ZIP名/哈希、加载器版本、HUD或No HUD、游戏版本、安装方式和Mod清单、主机或客户端、敌人/遮挡场景、准确故障时间及本次日志。区分游戏退出、系统蓝屏、整机无响应，不要用旧日志代替当前情况。

来源包括SentryAimRetention、BingusSharedLoader与KnowYourConstellation；各渠道加载器是否内置以包名为准，详细校验在provenance.json。公开发布和许可整理状态见[维护说明](maintenance.md)。
